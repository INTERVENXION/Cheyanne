# 夏安桌宠（XiaAn Pet）

一个 Windows 桌面虚拟桌宠：透明立绘常驻桌面、托盘后台运行、双击弹出聊天气泡，
接入任意 **OpenAI 兼容** 或 **Anthropic** 协议的大模型。

她会记得你说过的话——不是靠把整段历史塞进上下文，而是分三层：最近对话、滚动摘要、
结构化事实。每次重启都像重新见面，而不是把上次的结尾当成现在还在发生的事。

## 功能

- **无边框透明窗口**：用立绘的 alpha 通道生成窗口遮罩，鼠标可直接点到窗口外的桌面
- **7 种表情**：`idle / happy / sad / angry / surprised / shy / talking`，由模型输出的情感标签驱动
- **气泡对话**：聊天气泡贴在桌宠旁边，消息按宽度自动换行，不会被裁切
- **三层记忆**
  - 工作记忆：最近 N 轮原文（默认 100 轮）
  - 摘要记忆：把更早的对话压缩成一段叙述，按覆盖游标增量更新
  - 事实记忆：从对话里抽取结构化信息（喜好、约定、人物关系），按关键词检索
- **会话边界**：启动时算出"距上次见面多久"，让模型知道哪些是回忆、哪些是当下
- **多服务商**：DeepSeek / OpenAI / Claude / Gemini / Grok / Kimi / 智谱 GLM / 任意中转
- **API Key 加密**：用 Windows DPAPI 保存，只有当前 Windows 账户能解密
- **节日问候**：内建农历表（2024–2040），生日、端午、中秋等会换语气
- **可打包成单文件 exe**

## 环境要求

- Windows 10 / 11
- Python 3.9 或更高（开发环境 3.14.6）

> 代码里用到 DPAPI、透明窗口、系统托盘，这些是 Windows 专有实现，未在其他平台验证。

## 快速开始

### 方式一：直接运行打包版（不用装 Python）

仓库根目录已附带打好包的程序：

| 文件 | 作用 |
|---|---|
| `XiaAnPet.exe` | 主程序（约 48 MB，单文件、无需安装） |
| `夏安.exe` | 带图标的快捷启动器，会自动拉起同目录的 `XiaAnPet.exe` |

**双击 `夏安.exe` 即可启动。** 首次启动需要 10 秒左右解压，之后会快一些。

首次启动时她还没有 API Key，会提示：

> 指挥官，您好像还没有设置我的apikey，请右击我，在设置apikey中填写您的apikey。

右键桌宠 →「设置 API Key 与模型」，选服务商、填 Key、保存即可开始聊天。

> 这两个 exe 只在 Windows 上可用；想自己重新打包见文末【打包成 exe】。

### 方式二：从源码运行

```bat
git clone <仓库地址>
cd M200

python -m venv .venv
.venv\Scripts\activate

pip install -r requirements.txt

python main.py
```

第一次启动同样会提示配置 API Key。

### 操作方式

| 操作 | 效果 |
|---|---|
| 左键双击 | 打开 / 关闭聊天窗 |
| 左键拖拽 | 移动桌宠位置 |
| 右键 | 菜单：打开聊天、清空历史、设置 API Key 与模型、切换表情、退出 |
| 托盘图标 | 显示 / 隐藏 / 退出 |

## 配置模型

### 方式一：设置界面（推荐）

右键 →「设置 API Key 与模型」，选择服务商后**接口地址和模型名会自动填好**，
只需要粘贴 Key。改完可以点「测试连接」验证四要素是否都对。

### 方式二：编辑 `config.yaml`

```yaml
api:
  provider: "auto"        # auto / deepseek / openai / anthropic / gemini / grok / kimi / zhipu / custom
  endpoint: ""            # 完整 chat/completions 地址
  model: ""
  api_key: ""             # 留空，用设置界面填写（加密存储）
```

`provider: auto` 会按 endpoint/model 自动识别服务商。

### 支持的服务商

| 服务商 | 接口地址 | 认证方式 |
|---|---|---|
| DeepSeek | `https://api.deepseek.com/chat/completions` | Bearer |
| OpenAI | `https://api.openai.com/v1/chat/completions` | Bearer |
| Anthropic / Claude | `https://api.anthropic.com/v1/messages` | `x-api-key` |
| Google Gemini | `https://generativelanguage.googleapis.com/v1beta/openai/chat/completions` | Bearer |
| xAI / Grok | `https://api.x.ai/v1/chat/completions` | Bearer |
| Moonshot / Kimi | `https://api.moonshot.cn/v1/chat/completions` | Bearer |
| 智谱 GLM | `https://open.bigmodel.cn/api/paas/v4/chat/completions` | Bearer |
| 自定义 / 中转 | 自行填写 | Bearer |

> Claude 的请求格式与 OpenAI 不同（system 需要单独提出来、认证用 `x-api-key`、
> 返回是 content 数组），这些差异由 `src/providers.py` 自动处理，无需手工适配。

### 常用参数

| 配置项 | 说明 |
|---|---|
| `max_tokens` | 单次回复上限。默认 400；若服务商会在输出前消耗较多内部 token，需要调大 |
| `temperature` | 默认 0.8，仅在 `thinking: false` 时生效 |
| `timeout` | 请求超时（秒），默认 60；响应慢的服务商可调到 120+ |
| `thinking` | DeepSeek 专有的思考模式，桌宠场景必须保持 `false` |
| `send_thinking` | `auto` 只对 DeepSeek 发送该字段，切换其他厂商不会因未知参数报错 |

## 数据与隐私

所有运行时文件都在程序目录下，且已写入 `.gitignore`：

| 文件 | 内容 | 说明 |
|---|---|---|
| `api_key.dat` | API Key | **Windows DPAPI 加密**，只有当前 Windows 账户能解密 |
| `provider.json` | 界面里选的服务商 / 地址 / 模型 | 优先级高于 config.yaml |
| `chat_history.json` | 完整对话历史 | 私人内容，不要提交 |
| `memory_summary.json` | 摘要与覆盖游标 | 私人内容 |
| `fact_store.json` | 结构化事实 | 私人内容 |
| `session.json` | 上次见面时间 | 用于计算会话间隔 |

- API Key **不会**以明文出现在任何文件里（迁移前的旧配置除外，程序会自动搬走并清空）
- 如果要把项目拷到另一台电脑，Key 需要重新填——这是 DPAPI 的设计，不是 bug
- `config.yaml` 里刻意留空了 endpoint / model / api_key，仓库不携带任何作者的私人配置

## 自定义角色

角色设定在 `prompt.yaml` 中，修改后**无需重启**，下次对话即生效。

仓库里的 `prompt.yaml` 是通用版本。如果你想换成自己的私人设定：

1. 复制 `prompt.yaml` 为 `prompt.local.yaml`
2. 随便改
3. 程序会**优先读取 `prompt.local.yaml`**，且这个文件名已在 `.gitignore` 里，不会被提交

> ⚠️ 无论怎么改，**必须保留输出格式那段**：模型要返回
> `{"emotion": "...", "reply": "..."}` 的 JSON。`emotion` 只接受
> `happy / shy / surprised / sad / angry / neutral` 六个值，否则表情不会切换。

## 打包成 exe

```bat
pip install pyinstaller
python -m PyInstaller XiaAnPet.spec --noconfirm --clean
```

产物在 `dist\XiaAnPet.exe`（单文件，约 48 MB）。

部署时 `dist\` 需要包含：

```
XiaAnPet.exe
config.yaml  prompt.yaml  holidays.yaml
Image\
```

如果还想要一个"双击即启动"的外壳（避免任务栏出现控制台窗口），可以再打包启动器：

```bat
python -m PyInstaller launcher.spec --noconfirm --clean --distpath launcher_out
```

## 项目结构

```
main.py                 入口：创建 QApplication 与桌宠窗口
launcher.py             独立启动器（stdlib，用于生成轻量外壳 exe）
config.yaml             API 与记忆配置
prompt.yaml             角色提示词（通用版）
prompt.local.yaml       私人提示词（可选，已 gitignore）
holidays.yaml           节日与时段问候
XiaAnPet.spec           PyInstaller 打包配置
launcher.spec           启动器打包配置

src/
  api.py                共享 HTTP 层：请求组装、错误翻译、token 用量统计
  providers.py          多服务商适配：请求形状 + 响应解析
  provider_config.py    界面选择的服务商设置（provider.json）
  secret_store.py       API Key 的 DPAPI 加密存储
  config_manager.py     配置读取（YAML 多编码容错）+ 密钥解析与迁移
  llm_client.py         对话主流程：上下文装配、情绪解析、历史落盘
  chat_dialog.py        聊天窗、气泡、启动问候、后台摘要线程
  settings_dialog.py    设置界面（服务商 / 地址 / 模型 / Key / 测试连接）
  pet_window.py         桌宠窗口、透明遮罩、托盘、右键菜单
  sprite_manager.py     立绘加载与尺寸归一化
  persistence.py        原子写入 + 多编码读取 + 损坏文件隔离
  session.py            会话边界：上次见面时间与间隔描述
  lunar.py              农历表（2024–2040）
  memory/
    memory_manager.py   三层记忆的装配与归档调度
    summarizer.py       增量摘要与合并
    fact_store.py       事实抽取、去重、检索

tests/                  18 个独立测试脚本 + 1 个隔离辅助（见下）
tools/                  配置同步、图标生成、农历表生成
docs/                   两篇设计说明
```

## 测试

测试**不是 pytest 框架**，每个文件都是可独立运行的脚本：

```bat
python tests\test_providers.py          # 多服务商请求/解析（104 项断言，不联网）
python tests\test_api_key_store.py      # DPAPI 加密与迁移（32 项）
python tests\test_memory_coverage.py    # 摘要覆盖与每轮注入（29 项）
python tests\test_prompt_override.py    # 提示词优先级 + 内容纯净度（30 项）
python tests\test_robustness.py         # 并发写、损坏文件、编码容错
python tests\test_fixes.py              # 历史 bug 回归
python tests\test_gui.py                # GUI 构造链
python tests\test_bubble_render.py      # 气泡文字不被裁切
python tests\test_session.py            # 会话边界
python tests\test_session_scenarios.py  # 边界场景
python tests\test_summary_merge.py      # 摘要合并
python tests\test_working_memory.py     # 工作记忆窗口与溢出
python tests\test_api_key_ui.py         # 首次启动提示与补问候
python tests\test_token_usage.py        # token 用量统计
```

> ⚠️ `test_live.py`、`test_continuity.py`、`test_greeting_live.py`、
> `test_greeting_continuity.py` 会**真实调用 API**，会产生费用，只在需要验证线上行为时运行。

测试会把自己产生的数据重定向到临时目录，并在结束时校验用户真实数据未被改动
（见 `tests/test_isolation.py`）。

## 已知限制

- **仅 Windows**：DPAPI、透明遮罩、托盘都依赖 Win32
- **测试需逐个运行**：没有 pytest 收集器，CI 集成需要自己写脚本
- **首次补齐历史摘要**：如果历史很长，第一次启动会连续发几个请求把旧对话压成摘要，
  期间可能较慢
- **不同模型对 JSON 的遵循度不同**：Claude / GPT 偶尔会用 markdown 代码块包裹，
  程序有兜底剥离，但角色扮演质量仍取决于模型本身、需要微调 `prompt.yaml`
- **摘要是有损的**：压到一两千字之后，久远的细节必然会丢

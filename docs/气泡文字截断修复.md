# 聊天气泡文字截断 — 排查与修复

> 现象：UI 里只显示「好，指挥官先忙，我」，
> 而 LLM 日志显示返回的是完整的「好，指挥官先忙，我等你。别太晚哦。」

---

## 一、先排除数据链路

第一步是确认问题出在"取到的文本"还是"画出来的文本"。

用日志里的原始字符串跑完整链路：

```
原始字符串     : {"emotion": "neutral", "reply": "好，指挥官先忙，我等你。别太晚哦。"}
解析 reply     : '好，指挥官先忙，我等你。别太晚哦。'   (17 字符)
_sanitize_reply: '好，指挥官先忙，我等你。别太晚哦。'   (17 字符)
_truncate_reply: '好，指挥官先忙，我等你。别太晚哦。'   (17 字符)
字数上限       : 80
```

三级处理**全部保留完整文本**。所以：

- ❌ 不是 `_parse_emotion_json` 的正则截断
- ❌ 不是 `_sanitize_reply` 的术语过滤
- ❌ 不是 `_truncate_reply` 的字数截断
- ✅ 问题在**渲染**

> 排查中踩过的坑：offscreen 平台（`QT_QPA_PLATFORM=offscreen`）
> 没有真实字体，度量与真机不同，**无法复现**这个问题。
> 必须在真实 Windows 平台 + 设置与 main.py 一致的
> `QFont("Microsoft YaHei", 9)` 才能复现。

---

## 二、复现

在真实平台渲染截图里的同一段对话，立刻暴露：

```
气泡2（好，指挥官先忙，我等你。别太晚哦。）
  body 尺寸   : 117 x 19     ← 只有一行的高度
  换行所需    : 130 x 38     ← 实际需要两行
  判定        : ⚠ 高度不足，会裁掉第二行
```

**文本要折成两行，但布局只给了一行的高度，第二行被裁掉。**

---

## 三、根因

`QLabel` + `setWordWrap(True)` 在本项目的布局栈里
**无法正确上报"给定宽度下的换行高度"**：

```
QScrollArea → chat_widget(QVBoxLayout) → ChatBubble(QFrame)
    → QVBoxLayout → QLabel(wordWrap=True)
```

实测证据：

```
body 的 sizePolicy.hasHeightForWidth() == True    ← Qt 声称支持
body.heightForWidth(400)                == 19     ← 却只返回一行高度
```

`QLabel` 内部是逐行绘制的，无法对"整体文本"做整形（shaping），
所以它算不出"这段文字在这个宽度下会折成几行"。
结果布局按一行给高度，多出来的行被静默裁掉。

### 雪上加霜的两个改动

排查过程中还发现之前的两次修改各自引入了新问题，都已修正：

1. **`resizeEvent` 里对 label 调 `setMaximumWidth`**
   布局先用旧宽度算好高度，再改宽度会让文字重新折行，
   但布局**不会**重算高度。这是最初引入该 bug 的直接原因。

2. **`minimumSizeHint()` 用最小宽度算高度**（我自己引入的）
   文本在 60px 下会折成 5 行，返回 98px；配合
   `QLayout.SetMinimumSize` 约束，气泡被强行撑到 98px 高，整屏空白。
   → 最小高度就应该是一行。

## 四、修复

### 1. 新增 `_WrapLabel`：自行计算换行高度

用 `QFontMetrics` + `Qt.TextWordWrap` 精确算出给定宽度下的换行高度，
并让 `sizeHint` / `minimumSizeHint` / `heightForWidth` 三者一致：

```python
def _wrapped_height(self, width):
    fm = QFontMetrics(self.font())
    flags = int(Qt.TextWordWrap) | int(self.alignment())
    rect = fm.boundingRect(QRect(0, 0, max(1, width), 10000), flags, self.text())
    return rect.height() + 2      # 余量，防不同 DPI 下末行被裁
```

宽度按"自然宽度"取空间，超过可用宽度才退化为换行 ——
这样短消息不会被无故折行：

```python
def _effective_width(self):
    return max(60, min(self._natural_width(), self._avail_width))
```

### 2. 自校正高度（关键）

即使 `heightForWidth` 正确，布局在宽度变化后仍不重算高度。
所以在每次尺寸/几何变化后主动核对一次，不够就顶上去：

```python
def _sync_height(self):
    needed = self._wrapped_height(self.width())
    if self.minimumHeight() == needed and self.maximumHeight() == needed:
        return
    self.setMinimumHeight(needed)
    self.setMaximumHeight(needed)
    parent.layout().invalidate()
    self.updateGeometry()
```

在 `resizeEvent` 与 `QEvent.FontChange/StyleChange/LayoutRequest` 时触发。
这段是必需的 —— 只靠 `heightForWidth` 在"运行中缩放窗口"的场景下仍然会截断。

### 3. 气泡按实际可用宽度约束

不用魔法数字，取滚动区视口的真实宽度：

```python
base = scroll.viewport().width() or dialog.width()
avail = max(160, base - 16 - 40 - 16)   # 滚动条余量 + 用户气泡 40px 偏移
body.set_available_width(avail - 20)    # 减去气泡左右内边距
```

> 早先用 `window().width() - 110`，比真实可用宽度小太多，
> 长句被多折一行，多出来的那行又被裁掉。

## 五、验证

新增回归测试 `tests/test_bubble_render.py`，覆盖：

- **9 种文本**：截图原句、用户长句、极短、单行、超长必然换行、
  含英文数字、纯中文无标点、多省略号与顿号
- **6 种窗口宽度**：320 / 340 / 356 / 380 / 420 / 520 px
- **运行中缩放**：340 → 300 → 360 → 500 → 380 逐步核对

每个气泡检查三项：

1. 正文控件完整落在气泡内（不溢出右边界）
2. 正文高度 ≥ 该宽度下换行所需高度
3. `body.text()` 与原始文本完全一致（没被截短）

## 六、留给后续的提示

Qt 的 `QLabel` 高度-for-宽度在复杂布局栈里不可靠。
若以后新增类似的"自适应高度文本"控件（例如支持 Markdown 渲染、
或富文本气泡），**不要**直接依赖 `QLabel.setWordWrap(True)`，
沿用 `_WrapLabel` 的思路：自己算高度，并在几何变化后自校正。

# 夏安「记忆连续性」改造方案

> 解决的问题：夏安每次启动会继承上次的摘要，导致出现
> 「刚准备上床睡觉又要下床工作」这类割裂感。

---

## 一、问题定位

### 现象

- 半夜 23:40 的对话以「准备一起睡觉」收尾
- 次日中午启动夏安，她仍处在那个场景里
- 你说「我要工作」，她的反应像是「你刚躺下怎么又起来了」

### 根因（三个独立缺陷叠加）

**① 历史消息没有时间戳**

`chat_history.json` 里只有 `role` 和 `content`：

```json
{"role": "user", "content": "嗯，实际上我这会有点累"}
```

模型完全无法判断「准备睡觉」是 3 小时前还是 3 天前。

**② 摘要没有时间感**

摘要是一串无时间锚点的叙述：

> 夏安向指挥官汇报武器保养后，坦露靠近时会紧张手抖……
> 深夜指挥官未睡，夏安热牛奶、亮小灯陪伴……
> 两人以心跳计数相约次日再见。

读起来永远是「正在发生」，不像「发生过的记录」。

**③ 提示词在鼓励"接续"而不是"回忆"（最关键）**

旧代码把记忆丢进上下文时写的是：

```
【记忆摘要 — 以下是你与指挥官之前对话的要点，你应当知道这些事】
【关于指挥官 — 你已知的长期记忆】
    ↓
"请根据对话自然地融入这些信息"
```

「融入」这个词的含义是**把旧信息当成当前状态的一部分**。
模型于是忠实地把上一场戏接着演下去 —— 它并没有出错，
是提示词要求它这么做的。

**④ 工作记忆里存着上次对话的原文（真正的元凶）**

这一点在实施过程中才暴露出来，而且是最关键的。

工作记忆（最近 40 条 = 20 轮）里存的**就是上次对话的逐字原文**。
启动问候发出时，上下文实际长这样：

```
[41] user      "嗯，我再搞定一些工作就去睡觉"
[42] assistant "指挥官...你刚才答应要一起睡的。现在又要去书房？"
[43] user      【系统通知】现在是中午12:00...（问候指令）
```

上一场的结尾原文**就贴在当前输入的正前面**。任何提示词层面的
"不要接着演"都要跟这种紧邻关系对抗，而且会输 ——
模型看到「你刚才答应要一起睡的。现在又要去书房？」紧接着一句
"现在打招呼"，最自然的解释就是继续那个场景。

所以真正的修复不是加提示词，而是**不把上次的原文带进新会话**。

---

## 二、改造思路

核心原则：**让夏安「记得」，但不「接着演」。**

概念上区分三种东西：

| 类型 | 含义 | 在上下文里的姿态 | 跨启动保留？ |
|---|---|---|---|
| 工作记忆 | 本次会话内刚发生的对话 | 正在进行，可直接接话 | **否** |
| 长期记忆（摘要/事实） | 过去某次相处的内容 | **记得**，是背景知识 | 是 |
| 会话边界 | 「现在是何时、距上次多久」 | 每次启动重建一次 | 每次重建 |

关键洞察：**"接续感"来自原文的在场，不是来自记忆的存在。**
只保留摘要和事实（都是"记得"层面的转述），
每次启动就是一次干净的重新见面，同时她依然什么都记得。

## 三、具体改动

### 0. 工作记忆改为「会话内」而非「跨启动」（核心修复）

新增配置项：

```yaml
memory:
  # false（默认，推荐）：每次启动从干净的对话开始，
  #   只保留"记得"层面的长期记忆（摘要 + 事实）
  # true：沿用上次最近 20 轮原文，接续感更强但会出现割裂
  restore_working_memory: false
```

`false` 时的上下文结构：

```
[0] system  角色 prompt
[1] system  会话边界（现在是何时、距上次多久）
[2] system  你记得的事（摘要）
[3] user    当前输入          ← 直接跟在 system 之后，没有旧对话原文
```

同时保证：**归档区间的摘要/事实提取照常进行** ——
不恢复原文不等于丢记忆，早期对话依然会被压缩进摘要和事实库。

### 1. 新增 `src/session.py` — 会话边界

每次启动生成一段「会话边界」提示，只在本次启动的**第一轮**
LLM 交互里注入一次：

```
【会话边界 — 非常重要，请仔细理解】
现在是 2026年09月29日 12:00。
你和指挥官上一次说话是在 2026年09月28日 23:40，距今大约 12 小时。

请注意以下几点：
1. 上次的对话已经结束了。中间隔着刚才提到的那段时间，
   那段时间里你们各自在做自己的事，你不知道具体发生了什么。
2. 下面是「你记得的事」，它是背景知识，不是正在发生的剧情。
3. 绝对不要接着上次的场景往下演。例如上次结尾是「准备睡觉」，
   那件事早就结束了，不要表现成「刚躺下又被叫起来」。
4. 指挥官现在说的话，优先于记忆里的任何状态。
   如果记忆里是「他要去睡了」，而他现在说「我要工作」，
   那就以「他现在要工作」为准 —— 这中间已经过去了一段时间。
5. 你需要做的是：像一段时间没见到他的人那样自然地重新打招呼，
   可以顺口提一句你记得的事，但不要把它当成刚刚发生的事。
```

时间差用口语化表达（`刚刚` / `大约 3 小时` / `大约 2 天` / `大约 1 个月`），
不报精确到分钟的秒数 —— 人回忆时不会那样说话。

**兼容性**：老存档没有时间戳，会走一个"不知道具体隔了多久"的变体，
但**其余规则完全相同**。（早期实现让老存档走极简分支，结果缺了
「不要接着演」「当下优先」这些关键规则 —— 而所有升级前的老存档
都会走那条分支，等于修复对老用户完全失效。已修正。）

### 2. 记忆注入改为「记得」姿态

`memory_manager.py` 里把记忆注入拆成两条路径，共用同一套措辞：

| 时机 | 行为 |
|---|---|
| 会话开始（含启动问候） | 主动注入摘要，姿态是「我记得」 |
| 对话中提起过往 | 按关键词检索（保持原有门控） |

关键措辞变化：

```
旧：请根据对话自然地融入这些信息，不要逐条复述或刻意提到。
新：以上是你记得的事，属于背景知识。
    如果和当前对话有关，可以自然地体现出来；
    无关就不用提，更不要逐条复述或提到这份清单本身。
```

摘要部分从「你应当知道这些事」改为「你记得的经历」，并明确：

```
请把这些当作「你记得的事」，而不是「正在发生的事」。
不要逐字复述，也不要主动把话题拉回这些往事上 ——
它们只是让你在指挥官提起时不会一脸茫然。
```

### 3. 消息加时间戳

新消息写入时带上 `ts` 字段（ISO 格式）：

```json
{"role": "user", "content": "...", "ts": "2026-09-29T12:00:00"}
```

用途有两个：
- 计算「距上次见面多久」（会话边界）
- 让摘要模型写出有时间感的摘要

另新增 `session.json` 记录进程的启动/退出时间，作为时间差的兜底来源。

### 4. 摘要时间感知

摘要提示词加入时间要求，并要求在开头注明发生时间：

```
【时间要求 — 很重要】
对话记录里带有时间标记（例如「指挥官 [2026-09-28 00:15]」）。
请在摘要开头注明这段对话发生的时间（例如「9月28日深夜」），
让读的人能判断这些事是"什么时候"发生的，
而不是一串没有时间感、容易被误当成"正在发生"的叙述。
```

从下一批摘要开始，摘要会长成「9月28日深夜，指挥官……」这样带时间锚点的形式。

### 5. 启动问候单独加强

问候是本次启动的第一轮 LLM 交互，也是唯一一次
**在没有任何当前输入的情况下、只凭记忆说话**的场合 ——
最容易出现场景接续。所以问候提示词里额外加入：

```
【重要】以下是这次问候的性质，请务必理解：
你是在隔了一段时间之后重新见到指挥官，不是在继续上一次的对话。
上一轮对话早就结束了。如果它结束在某个场景里（比如上次正在道晚安、
准备睡觉、或者刚从外面回来），那个场景已经过去了，
绝对不要表现成它还在进行中，也不要说"你刚才不是说要……"这类接续的话。
如果有记忆提到指挥官之前的状态（累了、要睡了、在忙），
那只是你的印象，不代表他现在还在那个状态。
```

同时问候会带上「距上次过去了多久」并据此调整语气。

## 四、效果对照（实测）

同一份记忆（上次结束于 23:40「准备一起睡觉」），不同时刻启动：

### 次日中午 12:00

| | 问候语 |
|---|---|
| 旧 | 指挥官，中午好呀。该吃午饭了，别又对着屏幕随便糊弄过去。 |
| 新 | 指挥官，中午好呀。**昨晚休息得怎么样？**记得吃点东西，别又忙忘了。 |

旧的完全跳过「隔了一夜」这件事，直接切到午饭 —— 这正是割裂感的来源。
新的自然带出「昨晚」，把时间跨度接上了。

### 次日清晨 07:30

| | 问候语 |
|---|---|
| 旧 | 指挥官，早上好呀。昨晚睡得怎么样？**我已经把早餐热好了，快起来吃吧。**（把她自己放进了卧室场景） |
| 新 | 早上好呀指挥官，昨晚睡得还好吗？**我煮了热水，要不要先来一杯？** |

### 隔两天 20:00

| | 问候语 |
|---|---|
| 旧 | 指挥官，晚上好。今天工作累不累？我煮了点热汤，你要不要过来喝一碗？ |
| 新 | 指挥官，晚上好呀。**好几天没见了**，你这两天忙不忙？ |

自动化 A/B 统计（每场景 3 轮）：

```
旧行为 穿帮总数: 2
新行为 穿帮总数: 0
```

## 六、已知限制

1. **老存档没有时间戳**
   你现有 168 条历史消息都没有 `ts`。首次启动会走"不知道具体隔了多久"
   的变体（规则完整，只是报不出具体小时数）。
   从这个版本开始的新消息会带时间戳，**再下次启动就能报出准确间隔**。

2. **老摘要没有时间锚点**
   现有摘要（281 字符）是无时间感的旧格式。
   它会在下次摘要合并时被重写为带时间的形式。

3. **"隔了多久"依赖正常退出**
   `last_end` 在退出时写入。如果程序被强杀（任务管理器结束进程），
   会退化为使用历史里最后一条消息的时间戳 —— 仍然够用。

4. **场景判断仍是提示词层面的软约束**
   模型偶尔仍可能自行接续。这是概率问题而非确定性 bug，
   已通过 A/B 实测把发生率降到 0/9。若仍观察到，可继续加强
   第 3、4 条规则的措辞。
